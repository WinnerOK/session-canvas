Initial verification on 2026-10-24 used Codex CLI 0.146.1 and desktop-bundled 0.163.0-alpha.11.2. The 2026-10-25 membership follow-up verified desktop-bundled 0.164.0-alpha.11.1. The native application implements the available subset and exposes the remaining limits directly in its connection UI.

## History compatibility

The adapter negotiates experimental APIs and tries paginated history first, then legacy `thread/read`. For incompatible desktop records, it reads the exact local rollout path supplied by the inventory. The reader resolves symlinks, restricts the file to the connected Codex home's session directories, and checks its session identity before displaying content. It never enumerates the home directory, writes source files, or derives live activity from file timestamps.

Legacy/local fallback entries are shown in pages of 40. Local reading is bounded at 128 MB per file and 16 MB per record, with incomplete trailing appends ignored. A missing file, identity mismatch, path escape, or size limit produces an error without an acknowledgment action for unloaded content. The local fallback shows dialogue actually recorded in that file; a fork's separately referenced ancestral history is not synthesized.

Only user messages, assistant messages, plans, and terminal outcomes are presented. Arbitrary tool payloads and hidden reasoning are excluded. Inventory/history never calls `thread/resume`; only the short-lived verifier resumes a just-created empty session to prove persisted history and ownership release. No real source calls `turn/start` or an approval-response method.

## Live desktop compatibility

The desktop runtime uses an app-owned stdio server rather than the default shared app-server control socket. Starting another stdio server reads the same saved inventory but cannot observe that runtime. Session Canvas therefore combines inventory/history with a separate read-only desktop follower. It validates same-user socket/peer ownership, uses little-endian length-prefixed JSON frames bounded at 64 MB, accepts only the verified snapshot/patch version, reconciles owner and revision identities, and requests a fresh snapshot on gaps. It declines all client-discovery requests and never claims ownership or submits work or approval decisions. Full conversation snapshots remain in memory only; SQLite receives the existing narrow session/result model.

The desktop socket format is private and may change with app updates. Missing sockets, disconnected owners, invalid frames, and unsupported stream versions clear affected live observations rather than preserve stale Running indicators. Reconnection requests fresh snapshots. Session Canvas neither creates the desktop IPC router nor starts/reconfigures a Codex daemon. Historical timestamps and file modification times are not used as live-state evidence.

## Remaining integration gate

The original full desktop integration gate has **not passed**. Real existing-session discovery, saved history, live desktop observation, local project membership, empty durable session creation, and existing-session membership mutation are implemented. Creation and moves are tested against the actual bundled server in isolated homes; they have not been exercised by changing the user's live projects/chats. Live-host move presentation, atomic concurrent-move protection, durable pending recovery, and exact native route resolution in every host version remain unverified. The live desktop observer and saved project identity mapping remain private compatibility adapters.

The native UI/domain/storage implementation can be evaluated independently through demo mode. Do not report the demo as a completed desktop integration. The narrow `SessionSource` boundary remains the integration point for existing-session moves and shared-host creation.

Official protocol reference: [App Server](https://learn.chatgpt.com/docs/app-server). Installed generated schemas take precedence when choosing methods for each CLI version.
